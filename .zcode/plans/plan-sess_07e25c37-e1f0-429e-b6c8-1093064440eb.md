# Phase 3: Auth package + authenticated CRUD

## Context (from scan)

The framework is Phase 1–2 complete: 11 packages, 127 passing tests on real PG/Redis, clean typecheck. Missing features are tracked in `docs/status.md` + the CLI's `planned.ts` (50 commands, exit 3). The documented next phase is **Phase 3 — Identity & Authorization** (framwork.md §6): "Deliver session authentication and personal API tokens first". Everything it needs already exists: the kernel's `resolveActor` hook (`packages/http/src/middleware/request-scope.ts:29`), `ResourcePolicy`/`denyAll`/`authorize` (`packages/http/src/authorization/policy.ts`), the framework-owned table pattern (`auditLogs` in `@framework/database`, re-exported under the `@framework:schema-exports` marker), and the `make:crud --access` gate that currently rejects everything but `public` (`packages/cli/src/generators/crud/generate.ts:65`).

**Explicitly deferred (stays "planned" in status.md)**: password recovery, email verification, OTP, JWT/JWK guard, login rate limiting (needs the cache package), `session:prune` command (the store will ship a `prune()` API ready for it).

## 1. `@framework/http` additions (principal plumbing)

- `FrameworkVariables` gains optional `principal: PrincipalLike | null` (`PrincipalLike = { id: string; abilities: readonly string[] }`) — additive, no breaking change to RPC types.
- New `requireAuth()` middleware → throws `unauthenticated()` (401) when `c.get('principal')` is null; `authenticatedPolicy` — a `ResourcePolicy` whose abilities all require an authenticated principal (spread base for generated policies).
- Unit tests in `packages/http/tests` for 401 + policy behavior.

## 2. New package `@framework/auth`

Depends on `core`, `http`, `database`. Layout follows package conventions (types in `./types`, tokens in `./constants`, runtime in modules):

| Module             | Content                                                                                                                                                                                                                                                                                                                                                                |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `hashing.ts`       | `PasswordHasher` contract + `BunPasswordHasher` (argon2id via `Bun.password`)                                                                                                                                                                                                                                                                                          |
| `schema/tables.ts` | Framework-owned `users`, `sessions`, `api_tokens` tables (uuid pk, `mode:'string'` timestamps, `abilities text[]`)                                                                                                                                                                                                                                                     |
| `principals.ts`    | `Principal` (id, via `session`\|`token`, abilities, user row, session/token id); session users get `['*']`                                                                                                                                                                                                                                                             |
| `user-provider.ts` | `UserProvider` contract + default `DatabaseUserProvider` over the users table                                                                                                                                                                                                                                                                                          |
| `session-store.ts` | create/resolve/rotate/revoke/prune — DB stores sha256 of an opaque random cookie token; sliding expiry                                                                                                                                                                                                                                                                 |
| `token-store.ts`   | issue (plaintext shown once, `fw_pat_…`)/resolve (hash lookup, expiry+revocation checked)/revoke/list; ability check                                                                                                                                                                                                                                                   |
| `auth-service.ts`  | `register`, `attempt` (hash verify → session rotation on login), `logout`, `issueToken`, `revokeAll`                                                                                                                                                                                                                                                                   |
| `guard.ts`         | `createAuthActorResolver(deps)` — passed as the kernel's `resolveActor`; authenticates from session cookie then Bearer (config order) **before** the request scope is created, so `ExecutionContext`/`currentActor()`/`logger()` see the real actor; sets `c.set('principal', …)`; memoized via the context (one DB lookup per request); throttled `lastUsedAt` update |
| `middleware.ts`    | re-export `requireAuth`, `requireAbility(ability)`                                                                                                                                                                                                                                                                                                                     |
| `routes.ts`        | `defineAuthRoutes(deps)`: `POST /auth/register`, `/auth/login`, `/auth/logout`, `GET /auth/me`, `POST/GET/DELETE /auth/tokens`; cookie flows wrapped in Hono's native `csrf()` (spec §11: built-in middleware, configurable origins); failures use the error catalog (401 `UNAUTHENTICATED`, 422 validation)                                                           |
| `provider.ts`      | `authProvider` registering hasher/stores/service as singletons from validated config (`auth.guards`, `session.{cookie,ttlSeconds}`, `token.{prefix,ttlDays}`)                                                                                                                                                                                                          |

Tests (`packages/auth/tests/`) against real PostgreSQL via `@framework/testing`: hashing, session create/rotate/revoke/expiry/sliding renewal, token hashing/abilities/expiry/revocation, unique-email constraint, and full endpoint flows — login/logout/me/token issue+revoke, 401s, CSRF rejection on cross-origin POST, and `currentActor()` propagation inside a handler.

## 4. CLI: `make:auth` + `--access authenticated`

- **`make:auth`** (moves out of `planned.ts` into a real command, `packages/cli/src/generators/auth/`): options `--guard session|api-token` (repeatable/comma list), `--dry-run`. Generates a thin `app/modules/auth/` module (provider wiring + route mount + config section) using the existing marker-based registration edits: `@framework:schema-exports`, `@framework:providers`, `@framework:routes`, config schema. Same staged-plan + rollback machinery as `make:crud`.
- **`--access authenticated`** unblocked: `definition.ts` schema → `z.enum(['public','authenticated'])`; `generate.ts` accepts it; policy template emits `...authenticatedPolicy`; route templates insert `requireAuth()` before `authorize(...)` when authenticated; OpenAPI `security: ['bearerAuth']` path (already in `templates-module.ts:114`) gets matching scheme definitions in the document builder.
- **Generated endpoint tests** for authenticated resources: fixtures create a user + issue credentials through the app's `AuthService` (works for either guard), assert 401 without credentials and 403 for insufficient ability alongside the normal CRUD assertions.
- Update tests that currently assert `authenticated` exits 3.
