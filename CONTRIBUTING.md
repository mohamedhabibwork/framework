# Contributing

## Setup

```sh
bun install
bun run db:up            # local Postgres (54329) + Redis (63799)
cp .env.test.example .env.test
bun run typecheck && bun run lint && bun run test
```

Tests run against real PostgreSQL and Redis (`bun run test`); endpoint tests
create and drop isolated `fw_test_*` databases automatically.

## Conventions

- **Commits:** conventional commits (`feat:`, `fix:`, `docs:`, `chore:`) — the
  changelog and release notes are generated from them.
- **Status honesty:** every feature lands with tests. [docs/status.md](docs/status.md)
  distinguishes validated / implemented / contracts / planned, and a feature
  without a passing test is "implemented", never "validated".
- **Architecture decisions** are recorded in [docs/architecture/decisions.md](docs/architecture/decisions.md).
- **Guides** are written in [`docs/`](docs/README.md) — that is the single source.
  `apps/docs` renders them and is regenerated by `bun run docs:sync`; never edit
  `apps/docs/src/content/docs/*.mdx` by hand.
- **Code samples must match real exports.** If a guide shows an API, it should be
  copied from a package's public surface, not invented.

## Documentation changes

```sh
bun run docs:sync     # regenerate the site pages from docs/*.md
bun run docs:check    # frontmatter, single H1, sidebar coverage, links, parity
bun run docs:build    # static build (needs Node ≥ 22.23.4; app code runs on Bun)
```

`docs:check` fails on stale generated pages, missing `title`/`description`,
a body `# heading` that duplicates the title, orphan pages, internal links to
routes that do not exist, a package missing from the catalog, or an Arabic
translation that is not listed in `src/data/i18n.ts`. CI runs it before building
the site.

Adding a page: write `docs/<slug>.md`, register it in
`apps/docs/scripts/docs-lib.ts` (`PAGES`) and in
`apps/docs/src/data/sidebar.ts`, then `bun run docs:sync && bun run docs:check`.

## Releases

Maintainers cut releases with `bun run release -- <version>` (gates on a clean
tree and green checks, bumps the version pins, updates `CHANGELOG.md`, tags, and
snapshots the docs on pre-1.0 minor bumps). Pushing the tag publishes the GitHub
Release.
